# Source-SHA256 reference

Computed 2026-08-31 on bf-repo from the tarballs already in
`/var/hud-build/cache/`, which is `docs/WORKFLOW.md` migration step 2.

**All 245 canonical definitions have their source tarball cached**, so the full
rebuild can run without fetching anything. This matters more than it sounds:
bf-repo currently has **no working CA certificate store**, so any HTTPS fetch fails
(`curl: (60) unable to get local issuer certificate`). The cache is why builds
worked at all, and why the rebuild can proceed while that is being fixed.

## What these hashes do and do not prove

They pin **the bytes that are already here** — the same bytes that built the
shipped packages. That makes builds reproducible against today's cache.

They do **not** prove the tarballs are what upstream published. Nothing on this
machine can check that while TLS verification is broken, so treat these as
trust-on-first-use. `zlib-1.3.1.tar.gz` was the one case that could be confirmed
independently: its hash matches the widely published upstream value
`9a93b2b7…f23`. The rest should be re-verified against upstream once the CA store
is repaired, **before** anyone treats a matching hash as an authenticity check.
